# Payload dashboard: adding a widget causes an endless hide/show loop

Minimal reproduction for a bug in `@payloadcms/ui` 4.0.0-beta.3 on the TanStack Start adapter.

In dashboard edit mode, adding a widget makes the admin page flicker constantly, and the `style` attribute on `<html>` keeps changing. It starts right after adding the widget, before saving.

This reproduction and its description were generated by an LLM (Claude) and checked in a real browser.

## Reproduce

Needs Node 24.15 or newer and pnpm.

```sh
pnpm install
pnpm dev
```

1. Open http://localhost:3000/admin and create the first user (the script below uses `dev@example.com` / `password123`).
2. Choose "Edit dashboard", click "Add" and pick any widget, for example "Collections".
3. The page flickers and never settles.

Or run the browser check (needs Google Chrome, and the dev server running):

```sh
pnpm repro
```

Result on my machine, 3 seconds after adding each widget:

| Widget             | Server function POSTs | `<html>` style mutations |
| ------------------ | --------------------- | ------------------------ |
| Welcome            | 361                   | 357                      |
| Collections        | 255                   | 246                      |
| Recents and pinned | 365                   | 358                      |
| Collection Query   | 361                   | 358                      |
| Upload files       | 327                   | 323                      |

Normal is 2.

## Cause

`RenderWidget` stores the result of the `render-widget` server function in state and renders it as `<>{Component}</>`. The decoded Flight tree contains lazy client components, so rendering it suspends. Nothing between the widget and the page-level `Suspense` in `RscNodeRenderer` (`@tanstack/react-start-rsc`) catches it. That boundary wraps the whole `AdminPage` and has an empty fallback, so React hides the entire page with `display: none !important`.

Why it repeats is my inference: when the page is shown again, effects re-run. `RenderWidget` fetches again and `RecentsAndPinned` fetches again, the new response suspends again, and so on.

## Fix

Give `RenderWidget` its own boundary:

```diff
-import React, { useCallback, useEffect, useRef } from 'react'
+import React, { Suspense, useCallback, useEffect, useRef } from 'react'
 ...
-  return <>{Component}</>
+  return <Suspense fallback={null}>{Component}</Suspense>
```

With that change every widget I tried makes 2 or 3 POSTs and no `<html>` style mutations.

## Workaround

[`workaround/@payloadcms__ui@4.0.0-beta.3.patch`](workaround/@payloadcms__ui@4.0.0-beta.3.patch) is a `pnpm patch` of `@payloadcms/ui` with the change above. To try it:

```sh
mkdir patches
cp workaround/*.patch patches/
```

Add this to `pnpm-workspace.yaml`:

```yaml
patchedDependencies:
  "@payloadcms/ui@4.0.0-beta.3": patches/@payloadcms__ui@4.0.0-beta.3.patch
```

Then run `pnpm install` and restart the dev server. Vite resolves the package by its store path and the patch changes that path, so a running dev server keeps serving the old file.

The patch changes two files. The source `RenderWidget.js` is not enough: the browser loads a prebundled copy in `dist/exports/client/index.js`, so that one has to change too.
